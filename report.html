LLM Quality Evaluation Report

1. Task 1 – Contradiction Extraction

For Task 1, I implemented a single-pass LLM approach.

The complete waterproofing specification was extracted from the PDF and sent to the model in one request.

The model was instructed to identify internal contradictions in four categories: Technical, Responsibility, Liability, and Schedule.

The result was returned as structured JSON containing: Statement1, Statement2, and Reasoning.

The main advantage of this approach is simplicity because it requires only one LLM call. The limitation is that the model must analyse the complete document at once, so some less obvious contradictions may be missed.

2. Goal of Task 2

The purpose of Task 2 was to compare Model 1 and Model 2 against the ground truth.

I also evaluated my Task 1 model as an additional comparison.

The ground truth contains 10 known contradictions from the waterproofing specification.

I wanted to check how many real contradictions each model found and how many false alarms each model produced.

3. Matching Method

The wording in the model outputs is not always exactly the same as the wording in the ground truth, so I did not use exact text matching.

For each contradiction, Statement1, Statement2, and Reasoning were combined into one text.

The text was converted into embeddings using all-MiniLM-L6-v2.

Cosine similarity was used to compare each model prediction with the ground-truth contradictions.

A prediction was counted as a match when the highest similarity score was at least 0.53.

A ground-truth contradiction could only be matched once, so multiple predictions could not receive credit for the same contradiction.

6. Interpretation

My Task 1 model achieved the highest precision and F1-score in this test.

Model 1 found 8 of the 10 real contradictions and produced 2 false alarms.

Model 2 found 6 of the 10 real contradictions and produced 4 false alarms.

My Task 1 model also found 8 of the 10 real contradictions, but it produced no false positives.

This means Model 1 and My Task 1 achieved the same recall of 0.80, while My Task 1 achieved higher precision.

7. Which Model Looks Safer

For this benchmark, My Task 1 model produced the cleanest predictions.

It found the same number of real contradictions as Model 1, but avoided the two false alarms produced by Model 1.

Model 2 performed worse because it missed more contradictions and produced more false positives.

A false positive can waste review time, while a false negative may allow a real contractual or technical issue to remain unnoticed.

Based on this benchmark, My Task 1 model would be a useful candidate for further testing.

8. Limitations

This evaluation uses only 10 known contradictions from one document, so the result should not be treated as a final production decision.

The evaluation also depends on the embedding model and the similarity threshold. The threshold of 0.53 was selected using this dataset and may not be optimal for other documents.

The Task 1 model uses a single-pass approach, so it must analyse the whole specification at once. On larger documents, some subtle contradictions may be missed.

For a production system, I would test the same approach on a larger set of manually reviewed documents and tune the threshold on a separate validation set.

9. Conclusion

Model 1 performed better than Model 2.

My Task 1 model achieved the highest precision and F1-score while maintaining the same recall as Model 1.

However, because this benchmark contains only 10 ground-truth contradictions, the results should be considered an initial evaluation rather than a final production decision.
